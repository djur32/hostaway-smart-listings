This is the principle behind everything that follows, in its smallest example. It shows why one editor per channel can’t work. Here is one fact, the way a host would say it: there’s a bathtub in bathroom 1. Now watch where it has to go. Airbnb files it as a simple amenity. Booking.com files it as a room facility, per bathroom. Vrbo only counts it in a full bathroom. Expedia files it as a kind of shower for the whole unit, so which bathroom it’s in is lost.

[Press] A host should say yes, there’s a bathtub, once, and never think about it again. Hospitable already does this translation for amenities. The host sets them once, and Hospitable pushes them to each channel. The shared layer extends that to every fact, one of a hundred standard fields. Today the product has only two states per field: one value, or Edit per channel. About 30 seconds.

Five menus drawn in Paper and reviewed on the frames, not tested with hostsThe menu

When Smart Listings needed a home, I drew five ways it could fit the property menu. I drew each on Hospitable’s real interface, and walked the same five tasks through each. A mode switch gives a focused workspace, but the rest of the property disappears while it’s on. One listing hub was the review’s pick. It has one copy of every fact, but the biggest migration. A sub-nav section moves nothing, but brings back two copies that drift. An assistant drawer changes nothing, but has no room and no home.

[Press] I chose channel-first. Shared comes first and holds each fact once. Then each channel has its own pages. They show the Base until you change something for that channel. The cost is a menu that grows with every channel, and that’s what the tree test has to check. About 45 seconds.
