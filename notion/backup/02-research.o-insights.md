### 1 · Per channel means money and stay rules more than words
The cleaning fee is customised per channel on 36% of multi-channel properties and the minimum stay on 30%; no text field passes 4.1% `SIMULATED`. The product already models a short-stay cleaning fee per channel `REAL·PRODUCT`.
![Share of multi-channel properties using "Edit per channel" on each field. SIMULATED data, real analysis; the 13 fields are the product's own, REAL·PRODUCT. Titles, descriptions and photos are not in this data.](https://prod-files-secure.s3.us-west-2.amazonaws.com/8b3ff55d-72c7-4307-9089-beb3df02707e/2bd307ea-0398-43a2-a26a-1569021a8f90/r-overrides-by-field.png)
**In the design:** tips cover pricing, availability and booking policies, on each channel's own pages. <mention-page url="https://app.notion.com/p/3eee18af1645811a82c4e772997ac875"/> · <mention-page url="https://app.notion.com/p/3eee18af164581178debffa0628f4703"/>
### 2 · An authored voice per channel is an optimiser's mode, not a default
Only the optimiser wanted different words per channel; the portfolio manager wanted one text adapted, and family and new hosts treat the description as a fact `SIMULATED`. The brief's hosts split the same way `REAL·BRIEF`. Booking⁠.com writes its own description (`REAL·PUBLIC`, [partner help](https://partner.booking.com/en-us/help/property-page/general-info/changing-your-property-description-or-room-details)). Moderate: the persona split rests on simulated sources only.
**In the design:** a channel field uses the Base until customised; Booking⁠.com's description is set by the channel; Smart Listings is opt-in. <mention-page url="https://app.notion.com/p/3eee18af164581178debffa0628f4703"/> · <mention-page url="https://app.notion.com/p/3eee18af1645816c86aee6acef674975"/>
### 3 · Explaining a suggestion raises acceptance, not checking
The explained suggestion was trusted more, yet only 2 of 5 caught a planted claim the facts didn't support `SIMULATED`. Platform AI that gets listings wrong already angers hosts (`REAL·PUBLIC`, [Airbnb Community](https://community.withairbnb.com/t5/Ask-about-your-listing/Their-Ai-category-decided-my-listings-were-farms-They-are-not/m-p/1773704)). So grounding is a rule, not a warning.
![A tip in the docked panel: what changes, then its why, each line sourced to the Knowledge Hub, guest messages or similar homes. The prototype; content SIMULATED.](https://prod-files-secure.s3.us-west-2.amazonaws.com/8b3ff55d-72c7-4307-9089-beb3df02707e/1f9adf47-0f43-48a0-adc1-8d7c4f073feb/tips-wifi.png)
**In the design:** one tip at a time, each with its why and sources; Knowledge Hub facts cited by name. <mention-page url="https://app.notion.com/p/3eee18af1645811a82c4e772997ac875"/> · <mention-page url="https://app.notion.com/p/3eee18af1645811f8fcfcbffc7cbb69d"/>
### 4 · See it before it's written, proof after
Hosts wanted to see a change before it reached a channel, then proof it arrived; a copy to restore later reassured only the optimiser `SIMULATED`. Today a save says nothing about what was sent where `REAL·PRODUCT`. The research found this about connecting a channel; applying it to every edit is an `ASSUMPTION`.
**In the design:** Canvas shows each channel's guest page; tips name their channel; Save sends each change with a receipt, and an accepted tip can be undone. <mention-page url="https://app.notion.com/p/3eee18af16458187b60ec60bb6c3c5c5"/> · <mention-page url="https://app.notion.com/p/3eee18af1645818496f9d13c2481a86d"/>
### 5 · Two stores of facts disagree
Only 14 of 28 filled facts read the same in Details and the Knowledge Hub, and the assistant answers from the Hub, which no channel reads `REAL·PRODUCT`. The Hub reads Details once and never updates (`REAL·PUBLIC`, [help centre](https://help.hospitable.com/en/articles/9716792-property-knowledge-hub-page)).
**In the design:** every fact lives once, in Shared; channels and the assistant read it; Hub facts feed the tips. <mention-page url="https://app.notion.com/p/3eee18af164581178debffa0628f4703"/> · <mention-page url="https://app.notion.com/p/3eee18af1645811f8fcfcbffc7cbb69d"/>
### 6 · Hosts already ask to edit once
The request to edit listing details once and have the channels update has 322 votes and is In Progress (`REAL·PUBLIC`, [feedback board](https://feedback.hospitable.com/p/two-way-sync-of-updates-to-listing-details)). Every simulated host ran a workaround instead `SIMULATED`.
**In the design:** a channel inherits every value from the Listing base and holds only what differs. <mention-page url="https://app.notion.com/p/3eee18af164581178debffa0628f4703"/> · <mention-page url="https://app.notion.com/p/3eee18af164581828521eb27e3e50737"/>
## How it was made
Simulated evidence (interviews, card sort, and the data planned in <mention-page url="https://app.notion.com/p/3eee18af16458150add8ef7c753dbd12"/>) clustered with real product and public evidence. None of it measures how common anything is.
